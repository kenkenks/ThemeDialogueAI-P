## Codex利用枠の測定方法

目的は、監督・調査・指示・レビュー・検証の作業ごとの消費傾向を観測し、継続可能な作業量の判断材料を得ること。契約プラン、上限、リセット周期、モデル、予算は未決定。固定の利用可能回数は仮定しない。

公式資料では、現在の枠は利用状況ダッシュボード、Codex CLIの残り枠は `/status` で確認できる。利用量はモデルやタスク・コンテキストなどで変わるため、依頼回数だけで推計しない。出典：[OpenAI公式 Pricing](https://learn.chatgpt.com/docs/pricing)（2026-10-28確認）。実際の契約と画面で観測できる指標を優先する。

1. 作業開始前に、日時・タイムゾーン、作業名・種別、要求ID、利用環境、契約プラン、モデルと設定、観測手段を記録する。分からない項目は「未確認」とする。
2. 表示される各利用枠の使用率または残量、枠の期間、次回リセット日時を開始時点で記録する。表示がない項目をゼロとみなさない。
3. 範囲を明確にした作業を一単位実施し、開始・終了時刻、成果物、修正や再実行の回数、検証結果を記録する。同時期の別作業があれば併記する。
4. 終了後、同じ観測手段で同じ枠の値を記録する。使用率なら「終了時 − 開始時」、残量なら「開始時 − 終了時」を消費差分とする。百分率の差はパーセントポイントで記録する。
5. 期間中にリセット・プラン変更・追加枠購入があれば単純差分を無効として記録する。別作業との共有枠、表示丸め、反映遅延があれば、この作業だけの厳密な消費量とは扱わない。
6. 比較可能な条件で作業種別ごとに複数回測定し、消費差分の範囲、所要時間、得られた成果を比較する。回数や時間をトークン数・料金に推測換算しない。Gemini API／Firebaseの費用は別の測定対象とする。

記録項目の例：`作業名 / 要求ID / 開始・終了日時 / プラン / モデル・設定 / 観測元 / 枠の期間 / 開始値 / 終了値 / リセット日時 / 消費差分 / 所要時間 / 成果 / 再実行 / 他作業・測定上の制約`。

測定回数、記録先、測定担当、消費量の許容値、残量が少ない場合の運用は未決定。本書には実測値を記載していない。
