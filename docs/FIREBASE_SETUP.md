# Firebase事前設定と作業担当

> 公開用資料：旧履歴の識別子や内部参照を省略しています。記載日当時の仕様・計画・実験記録であり、現在の実装範囲と検証手順はREADMEを参照してください。

目的：Googleログインとユーザーマスタの実装・検証に必要な環境準備を、担当と実施条件付きで明示する。

対象範囲：ローカル検証環境と実Firebaseの事前設定。今回行うのは本書の作成のみ。プロジェクト作成、設定変更、課金設定、Rules反映、デプロイは実施していない。

基準日：2026-10-28。設計は [AUTHENTICATION_DESIGN.md](AUTHENTICATION_DESIGN.md)、実装指示案は [EXP-002/REQUEST.md](ai-collaboration/EXP-002/REQUEST.md) を参照する。

## 実施順序と担当原則

1. Codexが設計と指示書を用意する（今回）。ユーザーが後日、実装開始を明示して指示書を渡す。
2. Google AI Studio Buildがローカル実装・エミュレーター用ソースと試験を作り、Codexがレビューする。実クラウドの設定を自動で追加しない。
3. 実接続を試す前に、ユーザー（Firebaseプロジェクト管理者）が以下の実クラウド設定を行う。各操作は今回の許可に含まれず、後日の設定変更許可を要する。
4. 管理者がレビュー済みRulesを反映し、ユーザーが実Googleログインを操作する。Codexは変更内容・試験結果を確認する。プロバイダ設定だけで未検証Rulesを公開しない。

実装AIは設定値の要求と不足の報告を行い、Google側の「Enable Firebase」「Publish」や自動プロビジョニング機能を使用しない。UIに同意カードが出た場合も作業を進めず、管理者の別操作へ切り分ける。

Googleログインの設定は [公式Google認証手順](https://firebase.google.com/docs/auth/web/google-signin)、DB作成と開始モードは [Firestore開始手順](https://firebase.google.com/docs/firestore/quickstart) に従う。Googleログイン画面で不要な追加スコープは要求しない。

Firebase WebのAPIキーはプロジェクト識別に使われ、サービスアカウント秘密鍵やGemini APIキーと同じ秘密情報ではない。ただしRules・必要なAPI制限等の確認は省略せず、環境ごとの構成管理を行う。[Firebase APIキーの説明](https://firebase.google.com/docs/projects/api-keys)

## 実行環境の注意

- 初期版はポップアップ方式。AI Studioの埋め込みプレビューでGoogle認証が失敗しても、場当たり的にドメイン・ルールを広げない。独立したブラウザー／ローカル開発ホストで確認し、必要な対応は別の設計変更として扱う。
- プロジェクトID・所在地・ドメイン・サポートメールはユーザー固有の環境値。AIが例示値を実値として確定しない。
- AuthとFirestoreのエミュレーター設定は明示的な開発モードでのみ有効にし、実モードと混在させない。実接続は設定完備と管理者の許可を確認してからにする。
- 本段階ではGemini API、Cloud Functions、Hosting／App Hosting、Storage等の設定は不要。AI StudioのホスティングやCloud Run連携も有効化しない。
- Spark／Blazeの選択や課金変更は自動で行わない。採用サービスの最新条件と予算を管理者が確認する。今回、無料で必ず運用できるという保証はしない。

## 開始前にユーザーから必要な情報

ローカル実装開始時は「EXP-002実装を開始する」という明示と資料の版、利用するGoogle AI Studio環境の確認が必要。実Firebase接続時に初めて、対象projectId、所在地、Web構成、サポートメール、開発URL、許可ドメイン、管理者の設定結果と設定変更許可を確認する。これらの未確定だけを理由に、後日のローカル実装準備まで止める必要はない。
